## Чем Foreman отличается от Docker + Nginx + Samba?
Foreman отвечает за управление жинезным циклом хостов, в то время как Docker/nginx/samba за ручуную настройку и развертывания изолированных сервисов и последующей связи между ними.

| Критерий | Foreman | Docker/Nginx/Samba |
| -| - | -|
| Повторяемость  | Высокая: конфигурация как код (templates + Ansible-роли), пересоздать хост - вопрос применения Host Group   | Низкая: ручные шаги, легко забыть или сделать по-разному в следующий раз |
| Масштабируемость | Хорошо масштабируется: одна роль/группа - много хостов | Плохо масштабируется: каждый сервер настраивается отдельно вручную |
| Config drift (рассинхронизация) | Контролируется: можно перепрогнать роли и вернуть к эталону | Высокий риск: конфиги расходятся со временем, никто не помнит "как было" |
| Инвентаризация хостов | Централизованная (facts, группы, статусы) | Отсутствует (ручной список/wiki) |
| Требуемые ресурсы/инфраструктура | Больше: сам Foreman + БД + Smart Proxy требуют отдельного сервера и обслуживания | Минимальные: пара контейнеров, никакой доп. инфраструктуры |
| Точки отказа | Foreman - дополнительный критичный сервис (хотя уже настроенные хосты продолжают работать) | Точек отказа меньше, но и защиты/отказоустойчивости тоже нет |
| Целесообразность применения | Десятки-сотни хостов, требования к единообразию, аудиту, регулируемая среда | 1–3 сервера, прототип, быстрые эксперименты |
| Что покрывает | Provisioning ОС + configuration management "под капотом" (NTP, security policies и т.п.) | Только прикладные сервисы, без управления жизненным циклом ОС |
